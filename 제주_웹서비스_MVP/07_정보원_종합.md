# 07. 정보원 종합

[정보원_조사/](정보원_조사/) 01~05 를 합쳤다. 01 본부, 02 학과, 03 학식·생활, 04 학교 밖, 05 도메인 탐색.
각 칸의 [확인]/[추측] 은 원래 보고서를 따른다. 02 만 검색엔진 사본으로 쓴 부분이 많아서 [검색] 표시가 따로 있다.

## 0. 먼저 볼 것

학교 사이트는 거의 다 artpq CMS 하나로 돌아간다. 본부, 생활관, 진로취업, 국제교류, 학과까지 목록 HTML 꼴이 같아서 파서 하나로 대부분을 읽는다(01·05 [확인], 학과는 02 [검색]).
글 번호 seq 도 사이트 전체가 같이 쓴다. 다만 학과가 본부 글을 다시 올리면 새 seq 가 붙는다(02 [확인]). 중복은 seq 와 제목 비교를 같이 써야 걸러진다.

막히는 곳은 세 군데뿐이다.

- 1호관 점심·저녁 메뉴: 인스타그램 이미지에만 있다.
- 비교과 신청·마일리지: 포털 로그인 안쪽이다.
- 에브리타임·학생회 SNS: 로그인이 필요하거나 약관이 막는다.

핵심 게시판·식단 주소 21개를 11/21 22:50 KST 쯤 직접 받아서 보고서와 맞춰 봤다(7절). 대부분 맞았고, 고칠 것이 셋 나왔다. 재게시 글의 seq, 단과대 첫 화면, 쉐프스키스 접속 차단이다.

## 2. 학식

학식 다섯 곳 중 네 곳은 학교 홈페이지 표로 바로 읽힌다. 남는 한 곳이 1호관(쉐프스키스)의 점심·저녁이다.

| 식당 | 끼니 | 가져올 곳 | 방법 | 주의 |
|---|---|---|---|---|
| 백두관(생협) | 중식1·중식2·석식, 월~금 | 학교 `firstfixmenu.htm` | `caption` 이 식당 이름인 `table` 을 읽는다. `thead th` = 끼니, `tbody tr th` = 날짜, `td` 를 `<br>` 로 나눠 메뉴 배열 | 중식2 하루 150개 한정. 방학엔 중식2·석식 없음 |
| 6호관(아이비푸드) | 조식(일반·간편)·중식·석식, 월~일 | 학교 `fixfirst.htm` | 백두관 파서 그대로 | 학교 페이지가 늦게 바뀐다. 이번 주 날짜가 아니면 "아직 안 올라옴"으로 표시하고 업체 게시판 이미지 링크를 대신 건다 |

| 1호관 아침(천원의 아침밥) | 일~금 | `chefskiss.co.kr/morning` | 목록에서 가장 큰 `idx` 글 → 본문 텍스트 표 | 토·공휴일 휴무 |
| 1호관 점심·저녁 | 하루 2끼 | 인스타 `chefskiss_jnu` | 아래 | — |

인스타그램은 직접 읽을 수 없었다. 프로필은 JS 껍데기, 내부 API 는 로그인 요구로 404 였다(03 [확인]). 03 은 크롤러인 척하는 우회는 시도하지 않고 멈췄다. 맞는 판단이었다.

대신 쉐프스키스 홈페이지 첫 화면의 인스타 위젯이 최근 25개 게시물의 캡션과 링크를 HTML 에 넣어 준다(03 [확인]). 고를 수 있는 길은 넷이다.

1. 위젯에서 캡션과 게시물 링크만 보여 준다. "11/21 중식: 고기국수 … [인스타에서 보기]". 이미지는 저장하지 않는다. 캡션엔 대표 메뉴 한두 개만 있다.
2. 쉐프스키스에 주간 메뉴를 홈페이지 게시판에 텍스트로 올려 달라고 부탁한다. 아침 메뉴는 이미 그렇게 하고 있으니 무리한 부탁은 아니다.
3. 팀원이 `meals_manual.json` 하나를 GitHub 에서 직접 고친다.
4. 이번 MVP 에선 1호관 점심·저녁을 빼고 인스타 링크만 둔다.

제안은 4로 시작해서 2를 부탁해 보는 것이다. 1은 업체 사이트를 긁는 것이라 5절의 robots 문제와 같은 고민이 생긴다.

하나 더 있다. 11/21 밤 이 세션(클라우드 IP)에서 `chefskiss.co.kr` 은 첫 화면도 `/morning` 도 robots.txt 도 403 "접근이 제한되었어요" 였다(7절 [확인]). 03 조사 때(로컬 PC)는 열렸으니 아임웹이 해외·데이터센터 IP 를 막는 것으로 보인다 [추측]. GitHub Actions 도 데이터센터 IP 라서 아침 메뉴 수집도 막힐 가능성이 크다. 그러면 1호관은 아침까지 링크로만 두거나, 집 PC 에서 하루 한 번 받아 push 해야 한다. OCR·비전 AI 로 메뉴판 이미지를 읽는 건 비용과 오인식 때문에 MVP 밖에 둔다.

6호관은 토요일 밤까지 학교 페이지가 지난주(11/16~22) 그대로였다. 다음 주 분은 업체 게시판에 11/19 "11월 4주차" 이미지로 먼저 올라왔다.

## 3. 학과 홈페이지에만 올라오는 공지 모으기

본부 공지에 없는 글이 학과 게시판에 꽤 있다. 학과 국가근로장학생 선발, 대학원 복지장학, 튜터링, 트랙 선발, 졸업 신청, 학부 시간표, 병원 약사·간호사 채용 같은 것이다(02 4절 [검색]). 학생 입장에선 이런 글이 오히려 더 급하다.

방법은 이렇게 잡았다.

1. 학과 게시판 목록(`sources/departments.yaml`)을 한 번 만든다. 본부 `colleges.htm` 에서 학과 사이트 링크를 뽑고, 사이트마다 "공지" 메뉴를 찾는다. 경로가 학과마다 달라서(`/index/community/notice.htm`, `/community/notice.htm`, `/degree/notice.htm`, 서브도메인과 다른 경로 이름) 자동으로만 만들면 틀린다. 마지막에 사람이 훑어본다.
2. 수집은 본부와 같은 파서로 첫 페이지만. 학과 게시판은 글이 적어서 하루 1~2회면 충분하다.
3. 사용자는 화면에서 "내 학과"를 고른다. 학과 글은 고른 학과 것만 보인다.
4. 본부 글을 학과가 다시 올리는 일이 잦다. 자매국수 장학 글은 본부 282814, 약학대학 282815, 간호학과 282825 로 seq 가 다 달랐다(02 [확인]). 그래서 제목 정규화 + 날짜 3일 안으로 합치고, 본부 글을 대표로 둔 채 "약학대학·간호학과에도 게시" 로 표시한다.
5. 6개월 넘게 글이 없는 게시판은 목록에서 빼 두고, 학기마다 목록 만들기를 다시 돌린다.

MVP 에선 학과 전체를 하지 않고, 테스트할 학생들의 학과부터 넣기를 제안한다. 약학대학 하나만 해도 "학과 선택" 기능을 보여 줄 수 있다.

## 4. 수집 방법 설계 (제안)

```
GitHub Actions (cron)
  └ collect.py
      ├ sources.yaml / departments.yaml 을 읽음
      ├ 정보원마다 파서 호출 (artpq_table, artpq_card, pyxis_json, rss, foodmenu_table, chefskiss_morning, gnuboard)
      ├ seq·제목으로 중복 제거, 분류·태그·마감일 붙이기
      └ site/data/*.json 으로 저장
  └ actions/deploy-pages 로 site/ 를 GitHub Pages 에 올림

브라우저 (정적 HTML + JS)
  ├ data/items.json, data/meals.json 을 받음
  ├ 관심사(키워드·학과·분류)는 localStorage
  └ 관심사에 맞는 글만, 마감 임박 순으로 보여 줌
```

### 4-1. 파서

| 파서 | 맡는 곳 | 메모 |
|---|---|---|
| `artpq_table` | 본부 공지·채용·게시판, 생활관, 국제교류, clip, 센터, 학과 | 셀렉터는 01 2-1절. 날짜는 `YYYY-MM-DD`·`YYYY.MM.DD` 둘 다. 고정 공지(`tr.info`) 는 seq 로 거름. 인쇄용 주소 `?_layout=playout&_view=print` 로 받으면 양이 절반 남짓(02) |
| `artpq_card` | NEWS 보도자료 | `a[href*=act=view]@title`, `p.date` |
| `pyxis_json` | 중앙도서관 | `data.list[]` 의 `id`·`title`·`dateCreated` |
| `rss` | 제주대미디어 | 표준 RSS |
| `jedaero` | 산학 프로그램 | 칸: 유형·제목·담당·접수 시작·접수 종료·상태·D-DAY. 종료일을 마감일로 바로 씀. 유형이 공동연구·컨설팅·네트워킹인 건 교수·기업용이라 뺌. TLS 설정 따로 |
| `foodmenu_table` | 백두관·6호관·사라 | 03 4절. 메뉴 사이가 `</br>` 라서 html.parser 가 구분을 버린다. 셀 HTML 원문을 `</br>` 로 먼저 자를 것 |

### 4-2. 주기

GitHub Actions 의 cron 은 UTC 다. 한국 시각에서 9시간을 빼야 한다.

| 묶음 | 한국 시각 | cron (UTC) | 이유 |
|---|---|---|---|
| 본부·센터 공지 | 07·12·17·22시 하루 4회 | `17 22,3,8,13 * * *` | 가장 바쁜 게시판도 하루 10건 정도. 01 은 1~3시간, 05 는 하루 1~2회를 권해서 그 사이로 잡았다 |
| 학과 공지 | 07·19시 하루 2회 | `41 22,10 * * *` | 글이 적고 게시판 수가 많다 |
| 식단 | 매일 05시 | `7 20 * * *` | 6호관처럼 늦게 바뀌는 곳 때문에 주 1회로는 부족(03) |
| 학사일정·버스 | 학기 초 수동 실행 | `workflow_dispatch` | 1년에 몇 번 바뀜 |

정각을 피해 분을 흩어 둔 건 Actions 예약 실행이 정각에 몰리면 늦어지기 때문이다. 한 번 돌 때 본부·센터 요청은 12~15번(01 2-4절 추정), 요청 사이엔 2~3초 쉰다.

### 4-3. 저장 형식

`site/data/items.json` 에 최근 60일 글을 담는다.

```json
{
  "id": "jnu:283520",
  "source": "jnu-notice",
  "source_name": "본부 공지사항",
  "category": "장학",
  "title": "2027년 1학기 국가장학금 1차 신청 안내",
  "url": "https://www.jejunu.ac.kr/ara/noticesurvey/outEvent.htm?act=view&seq=…",
  "date": "2026-11-18",
  "dept": "학생복지과(장학)",
  "attachments": ["신청 안내.pdf"],
  "deadline": null,
  "first_seen": "2026-11-21T22:17:00+09:00"
}
```

- 사람 이름이 들어갈 수 있는 작성자 칸은 저장하지 않는다. 부서·학과 이름만 남긴다.
- 본문은 저장하지 않는다. 본문이 이미지 한 장인 글이 많고(01), 저작권 문제도 있다. 제목·날짜·첨부 이름·원문 링크만.
- `deadline` 은 제목에 `(~11/18)` 같은 표시가 있거나 jedaero 처럼 칸이 있을 때만 채운다.
- 60일치면 1,000건 안팎, 수백 KB 로 본다 [추측: 본부 2주 76건, clip 교외채용 2주 60건에서 어림].
- `site/data/sources.json` 에 정보원마다 마지막 성공 시각과 받은 건수를 둔다. 화면 아래에 "본부 공지: 3시간 전 갱신" 으로 보여 주면 사용자가 데이터가 낡았는지 안다.
- "새 글" 표시는 `first_seen` 으로 한다. Pages 에 이미 올라간 `items.json` 을 수집 시작 때 받아 와서 비교하면 저장소에 상태 파일을 따로 커밋하지 않아도 된다.

### 4-4. 관심사 (브라우저 저장)

- `localStorage` 에 `{ "dept": "약학대학", "keywords": ["장학", "근로"], "categories": ["장학", "수업"], "campus": "아라" }` 꼴로 둔다.
- 거르기는 브라우저에서 한다. 서버가 없으니 사용자가 무엇을 골랐는지 아무도 모른다. 발표 때 "로그인 없이도 개인화"를 설명하기 좋다.
- 기기를 바꾸면 관심사가 사라진다. 설정을 주소 뒤에 붙인 링크(`#dept=pharmacy&kw=장학`)로 내보내는 정도면 MVP 엔 충분하다.
- 알림(푸시)은 서버가 있어야 해서 뺀다. 대신 분류별 RSS 파일(`feed/장학.xml`)을 함께 만들어 두면 피드 리더로 받아 볼 수 있다 [제안, 2단계].

## 7. 실제 확인 (할 일 3)

처음엔 이 세션의 네트워크 정책이 학교 도메인을 막았다(프록시 CONNECT 403, WebFetch 는 DNS 실패). 학교 도메인과 몇 곳을 허용한 개인 환경을 새로 만들어 옮긴 뒤 11/21(토) 22:50 KST 쯤 받아 봤다. 요청 사이엔 2초씩 쉬었고, 한 번에 1~3초 걸렸다.

인증서부터 걸렸다. 01 이 적은 대로 학교 서버가 중간 인증서를 보내지 않아 검증이 실패했다. 중간 인증서를 구해 번들에 넣었다(Sectigo 배포 주소는 http 만 돼서, GitHub 에 공개된 사본을 받아 시스템의 Sectigo R46 루트로 서명을 검증한 뒤 썼다). 그 뒤로는 검증을 켠 채 모두 열렸다.

| 정보원 | 결과 | 보고서와 맞나 |
|---|---|---|

## 8. 정할 것

- 1호관: 점심·저녁은 2절 넷 중 무엇으로 할지. 아침도 쉐프스키스가 클라우드 IP 를 막아서, 링크로만 둘지 집 PC 에서 받아 올릴지.
- 학교에 알릴지: 과제 MVP 라도 robots 가 전체 차단이라, 메일 한 통 보내 두는 것을 권한다.
- 학과 범위: 약학대학만, 테스트할 학생들 학과까지, 전체 중 어디까지.
- MVP 코드와 사이트를 이 저장소에 둘지 새 저장소로 뺄지. 이 저장소엔 다른 과제 브랜치와 발표 메모가 같이 있고, 수집 워크플로가 하루 여러 번 돌면 Actions 기록과 알림이 섞인다. 새 저장소를 권한다.
- data.go.kr 키: 학교 밖 정보원(장학 CSV, 청년정책 API)을 2단계에 넣을 거면 가입·활용신청을 미리 해 둔다. 승인에 시간이 걸린다.
