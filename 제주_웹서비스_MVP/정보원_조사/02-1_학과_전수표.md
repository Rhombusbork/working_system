## 한눈에 보기

- **[확인] 모든 학과 사이트가 같은 CMS 를 쓴다.** 경로가 `/pub/dist/...` 로 같고 게시판 HTML 구조도 같다. 그래서 **파서 하나로 전체 학과를 수집할 수 있다.**
- **[확인]** 공지 목록은 **서버가 그린 HTML 표**로 온다(API·JS 로딩 아님). 목록과 본문 모두 로그인 없이 열린다. 예외: 의과대학 `학생게시판`·인트라넷은 포털 로그인이 필요하다.
- **[확인]** 실제로 받아서 게시판까지 확인한 사이트: 학부 사이트 **88개** + 대학원·총장직속 **13개**. 그중 공지 게시판 **100개**의 제목·날짜·링크를 뽑았다(목표 15개 이상 충족).
- **[확인]** 업데이트 빈도는 고르지 않다. 최근 90일에 10건 넘게 올라온 활발한 곳은 11곳, 보통(3~9건) 27곳, 드묾(1~2건) 32곳, 올해 학기 단위로만 올리는 곳 16곳, 2025년 이전에 멈춘 휴면 14곳.
- **[확인] 주의: `robots.txt` 가 `User-agent: * / Disallow: /`** 이다(cms.jejunu.ac.kr, pharmacy.jejunu.ac.kr 등). 수집기는 하루 1~2회, 첫 쪽만, 요청 사이에 간격을 두는 것으로 최소화하고, 가능하면 학교(디지털정보처)에 문의하는 것이 좋다.
- **[확인]** 학과 공지의 상당수(국가장학금, 발전기금 장학 등)는 본부 공지를 다시 올린 것이다. 학과에만 있는 글은 **학과 추천 장학, 채용·인턴, 국립대학육성사업 특강·프로그램, 학과 행사·졸업시험·상담 안내**다.

## 공통 CMS 패턴과 수집 방법

### 주소 규칙 [확인]

- 홈페이지: `https://<서브도메인>.jejunu.ac.kr/` (http 도 열림). 일부 학과(미래융합대학 4개 학과, 글로벌자율전공)는 `https://cms.jejunu.ac.kr/<사이트ID>/index.htm` 형태다.
- 게시판: `https://<서브도메인>.jejunu.ac.kr/<사이트ID>/<메뉴경로>/<게시판>.htm`
  - 사이트ID가 서브도메인과 다를 때가 있다: 예) `mls` → `mlsjeju`, `abs` → `aquatic`, `jupiter` → `computer`, `todaud` → `life`, `homemanagement` → `fhew`, `vetmed` → `vetmedmain`.
  - 메뉴 경로도 학과마다 다르다: `community/notice.htm` 이 가장 많고, `index/community/notice.htm`, `degree/notice.htm`, `square/notice.htm`(교육대학), `community/fc_notice.htm`(미래융합대학), `notice/notice.htm`(철학과) 등이 있다.
  - 그래서 **URL 은 규칙으로 만들기보다, 아래 표의 목록을 설정 파일(YAML/JSON)로 들고 가는 것이 안전하다.**
- **통합 호스트 [확인]:** `https://cms.jejunu.ac.kr/<사이트ID>/<경로>` 로도 같은 내용이 나온다(약학대학으로 확인, 같은 크기·같은 20행). 인증서 문제나 서브도메인 DNS 문제가 있으면 이쪽으로 바꿔 부를 수 있다. `www.jejunu.ac.kr/<사이트ID>/...` 는 안 된다.
- 쪽 넘기기: `?page=2` [확인]. 검색: `?qType=title&q=<검색어>` [확인 — 본부 공지에서 확인, 학과도 같은 폼].
- 본문: `?act=view&seq=<번호>` [확인]. `seq` 는 **모든 사이트에서 하나로 이어지는 번호**다(약학 282815, 수학 283531, 본부 283510 등). 사이트 간 중복 제거 키로 쓰기 좋다 [확인: 번호 체계 / 추측: 같은 글이 여러 사이트에 공유되면 같은 seq 인지는 미확인].
- 첨부: `?act=download&seq=<번호>&no=1`.
- 가벼운 화면: `?_layout=playout` 을 붙이면 머리·꼬리가 빠져 약 55KB → 33KB 로 준다 [확인, 표 구조는 같음].
- RSS·JSON API 는 찾지 못했다 [확인: 게시판 HTML 에 rss 링크 없음, 공유 메뉴의 RSS 는 주석 처리됨].

### HTML 구조 [확인]

```html
<p class="board-list-count">총 <strong>24</strong>페이지 / 현재 <strong>1</strong>페이지</p>
<div class="board-list-wrap">
  <table><!-- summary="학과공지사항 게시물 목록의 제목,작성자,작성일 정보" -->
    <tbody>
      <tr class=" info ">   ← 상단 고정글(공지)은 class 에 info
        <td>473</td>
        <td class="title text-left" ...><a href="/pharmacy/community/notice.htm?act=view&amp;seq=282815" title="...">제목</a></td>
        <td>첨부</td><td>작성자</td>
        <td class="nowrap">2026-11-03</td>
        <td>조회수</td>
```

- 파서: `div.board-list-wrap` 안의 `tr` → `td.title a`(제목·링크), `td.nowrap`(날짜), `tr.info`(고정글 여부).
- 날짜가 `2026-11-03` 과 `2026.10.08` 두 형식으로 섞여 나온다 → 둘 다 받아서 `-` 로 바꾼다.
- 고정글은 오래된 글이 맨 위에 올 수 있으므로 **"최신 글"은 날짜로 다시 정렬**한다.
- 표 주석의 `summary="…"` 에 게시판 이름(예: `학과공지사항`, `학과취업정보`, `…대학원 공지사항`)이 들어 있어 게시판 종류 구분에 쓸 수 있다.
- 본문은 `div.view-contents`, 작성일시는 `p.info` 에 `2026-11-03 11:58:41` 형태 [확인].

### 수집기 제안 [추측: 설계안]

1. 설정 파일에 `{학과, 사이트, 게시판 URL, 게시판 종류}` 목록(아래 표의 ✅ 줄, 약 100개)을 둔다.
2. GitHub Actions 에서 하루 1~2회, 각 게시판 **첫 쪽만** 받는다(요청 사이 1~2초). 100개 × 약 35KB ≈ 3.5MB.
3. 제목·날짜·링크·seq·고정글 여부를 뽑아 `seq` 로 중복을 없애고, 학과별 JSON 으로 쌓는다.
4. 본부 공지와 같은 제목은 "본부 공지 재게시" 표시를 붙여 사용자가 중복을 덜 보게 한다.
5. 휴면 게시판(2025년 이전에 멈춘 곳)은 주 1회로 줄인다.
