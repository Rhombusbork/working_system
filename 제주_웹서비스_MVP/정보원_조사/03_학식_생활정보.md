## 3. 인스타그램 chefskiss_jnu 수집 시험

|---|---|

| 크롤러 UA 위장 시험 | 하지 않음(우회 시도로 판단해 중단) |

- 게시 빈도 [확인]: 위젯 기준 매일 3~4건(전날 밤 메뉴공지 1 + 조식·중식·석식 사진). 11/15~11/22 거의 빠짐 없음.
- 이미지 안 글자: 메뉴공지는 이미지(메뉴판)라 **전체 메뉴를 텍스트로 얻으려면 OCR 또는 비전 AI 필요**. 캡션만으로는 대표 메뉴 1~2개만 나옴.
- 이용약관 [추측, 일반 지식]: 인스타그램 약관은 허가 없는 자동 수집(스크래핑)을 금지. 공식 Graph API(Instagram API with Instagram Login)는 **계정 주인이 토큰을 발급**해야 자기 게시물을 읽을 수 있음 → 운영자 협조 없이는 불가. oEmbed(Meta 앱 토큰 필요)로는 임베드 HTML만 가능.
- 현실적인 방법(추천 순):
  1. **아침은 chefskiss.co.kr/morning 표를 그대로 수집** (이미 텍스트).
  2. 점심·저녁은 **chefskiss.co.kr 위젯의 캡션 + 게시물 링크만** 보여 주기 ("오늘 1호관: 고기국수 … [인스타에서 보기]"). 이미지 파일은 저장·재배포하지 않음(저작권·만료). 이것도 업체 사이트 수집이므로 robots.txt 확인과 하루 1~2회 요청으로 제한.
  3. **운영자 협조 요청**: 쉐프스키스(연락처는 chefskiss.co.kr 하단)에 "주간 메뉴를 홈페이지 '오늘의 정식' 게시판에 텍스트로 올려 주기" 또는 Graph API 토큰 제공 부탁. '오늘의 정식' 게시판(`/today`)은 2026-09-11 이후 끊김 [확인].
  4. 대안: 팀원이 수동 입력(JSON 1개 파일을 GitHub에서 편집).
  5. OCR/비전 AI는 MVP 범위 밖으로 두는 것을 권장(비용·오인식).

## 4. 수집 방법 메모

- **공통 파서 하나로 4곳 해결**: 백두관·6호관·사라캠퍼스(그리고 형식 같은 페이지)는 같은 CMS 템플릿. `table` 중 caption이 식당명인 것 → `thead th`=끼니 이름, `tbody tr`의 `th`=날짜("11/23 (월)"), `td`를 `</br>`로 나누어 메뉴 배열. "미운영" 처리.
- **실행 시각**: 학교 페이지가 주 중 늦게 바뀌므로 Actions cron을 **매일 1회(예: 05:00 KST)** 로 두면 충분. 주 1회만 돌리면 6호관처럼 늦게 올라오는 곳을 놓침. 날짜가 이번 주가 아니면 "업데이트 전" 표시.
- **인증서**: `www.jejunu.ac.kr`는 인증서 체인 문제로 `curl` exit 60. Actions에서는 `verify=False` 대신 중간 인증서를 번들에 추가하는 편이 안전. http도 200이지만 일부 경로가 https로 302될 수 있음 [추측].
- **인코딩**: ibjejunu.co.kr 은 EUC-KR(cp949). 나머지는 UTF-8.
- **세션 쿠키**: `/camp/stud/foodmenu.htm` 은 JSESSIONID 쿠키를 주며 302. 하위 페이지를 직접 부르면 쿠키 없이도 200 [확인].
- **실시간 정보(순환버스 위치·도서관 좌석·시내버스 도착)는 정적 JSON과 맞지 않음** → MVP에선 링크 카드로 처리.
- **포털 로그인 정보는 절대 Actions 시크릿에 넣지 않는다**: 식단·학사일정은 모두 공개 페이지에 있음.
- 원본 HTML 견본은 조사용 임시 폴더에만 저장했고 이 저장소에는 넣지 않음.
