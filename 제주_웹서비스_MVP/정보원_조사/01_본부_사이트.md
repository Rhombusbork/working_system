# 정보원 조사 01 — 제주대 본부 홈페이지와 본부 산하 행정 부서 게시판

조사일: 2026-11-21 (토) 밤. curl(User-Agent `Mozilla/5.0`)로 직접 받아 보고 확인했다.
- **[확인]** = 실제로 받아서 본 것, **[추측]** = 확인하지 못한 짐작.
- "2주 글 수"는 2026-11-07 ~ 11-21 작성일 기준이다. 상단 고정 [공지] 글은 뺐다.

## 0. 먼저 알아 둘 것 (전체 공통)

1. **CMS 하나로 다 돌아간다 [확인]**. 본부(www)와 산하 기관 서브도메인(dormitory, intl, clip, iss, changup, counsel, hpc, support, glocal, forstudent, rotc 등)이 모두 같은 CMS다
   (오류 페이지에 `com.artpq.cmspq` 라고 나옴, 정적 파일 경로는 `/pub/site/<사이트>/`). 목록 HTML 구조가 똑같아서 **파서 하나로 거의 다 처리된다**.
2. **글 번호(seq)를 모든 사이트가 같이 쓴다 [확인]**. 예를 들어 seq=283520 한시임기제 합격자 공고는 www `recruit.htm` 과 clip `employ/recruit.htm` 에 똑같이 올라 있다.
   여러 게시판을 모으면 같은 글이 겹치니 **seq로 중복을 없애야 한다**.
3. **서버에서 다 그려서 준다 [확인]**. 목록은 HTML 안에 바로 들어 있다. JS/AJAX는 필요 없다. 예외는 중앙도서관(SPA)인데, 대신 JSON API가 있다.
4. **로그인은 필요 없다 [확인]**. 이번에 본 공지 게시판은 모두 로그인 없이 읽혔다(세션 쿠키 `JSESSIONID` 를 주긴 하지만 없어도 된다).
5. **RSS는 없다 [확인]**. 템플릿에 `${rssURL}` 아이콘이 주석으로 막혀 있고, `?act=rss` 를 부르면 빈 응답(0바이트)이 온다.
6. **HTTPS 인증서 체인이 불완전하다 [확인]**. Sectigo DV R36 중간 인증서를 보내지 않아서 검증에 실패한다(`Verify return code: 21`).
   http://도 200으로 똑같이 응답한다. 수집기에서는 ① http로 받거나 ② Sectigo 중간 인증서를 CA 번들에 넣거나 ③ `verify=False` 를 쓴다. ②가 가장 깔끔하다.
7. **robots.txt는 전부 `User-agent: * / Disallow: /` 다 [확인]** (www, dormitory, intl, clip, support, counsel 확인. lib는 302).
   기계적으로 보면 모든 크롤링을 거부한다는 뜻이다. MVP에서는 **느린 주기(예: 1~3시간에 한 번), 목록 첫 페이지만, 요청 사이 간격 두기, 출처 링크 표시**를 지키고,
   가능하면 학교(디지털정보처·홍보팀)에 쓰겠다고 알리는 것이 좋다. 과제 발표 때 "robots 정책과 그에 대한 대응"을 한 줄 넣는 것을 권한다.
8. User-Agent 없이 받아도 200이 왔다 [확인]. 해외 IP(GitHub Actions 러너)에서 막히는지는 확인하지 못했다 **[추측: 막힐 수도 있음 → 첫 실행 때 꼭 확인]**.

## 2. 수집 방법 (파서 설계 메모)

### 2-1. 공통 목록 파서 (artpq CMS, 표형) — 위 표의 거의 모든 게시판

URL 규칙 [확인]:
- 목록 `https://<호스트>/<경로>.htm`
- 분류 `?category=<번호>` (www 공지사항만: 203 일반, 197 봉사, 200 행사, 239 자료실, 320 학사, 321 수업, 322 등록, 323 장학)
- 페이지 `&page=N` (1부터 시작)
- **한 번에 많이 받기 `&pageSize=N`** — 50·100·300 모두 됐다 [확인] (`listCount` 는 안 됨). 100건이 0.7초, 300건이 2초였다
- 검색 `&q=<검색어>&qType=title|contents|writer|titlecontents`
- 글 보기 `?act=view&seq=<번호>`, 첨부 `?act=download&seq=<번호>&no=<1..>` (PDF 다운로드 200 확인)
- `_layout=none` 같은 부분 렌더링은 오류("View를 찾을 수 없습니다")가 났다

목록 셀렉터 [확인]:
```
행:        table tbody tr
고정 공지:  tr.info  (첫 td 에 "[공지]") → 매번 같은 글이 맨 위에 오니 seq 로 중복 제거
번호:       td:nth-child(1)  (고정 공지는 "[공지]")
분류:       span.article-category   (www 공지사항만)
제목:       td.title a  → 전체 제목은 a@title (본문 글자는 ".." 로 잘림)
링크:       td.title a@href  → seq= 를 정규식으로 뽑기
첨부:       a.badge  → 글자=첨부 개수, @title 안에 파일 이름 목록(HTML), @href=첫 첨부 다운로드
작성부서:   td.hidden-md-down 중 첨부 다음 칸 (예: "학생복지과(장학)")
작성일:     td.nowrap  (YYYY-MM-DD)   ※ jnuboard 는 nowrap 클래스가 없음 → 날짜 정규식으로
조회수:     마지막 td
마지막 페이지: .paging a.btn-right@href 의 page=
```
상세 페이지 [확인]: `div.board-view` 아래 `p.title`(분류 포함 제목), `p.info`(작성자·작성일 시각·조회수), `div.view-contents`(본문),
`p.info a[href*=act=download]`(첨부). **본문이 이미지 한 장인 글이 꽤 있다**(예: 국가장학금 1차 신청 안내가 jpg 한 장). 그래서 MVP는 본문을 요약하지 말고 **제목+링크+첨부 이름**만 보여 주는 것이 현실적이다.

변형 2가지:
- 카드형(NEWS `promotion/jnunotice/notice.htm`, fund): `a[href*="act=view"]@title` 이 제목이고 `p.date` 또는 `span.date` 가 날짜다.
- 날짜 칸 클래스가 없는 표(jnuboard): 행 안에서 `\d{4}-\d{2}-\d{2}` 를 찾는다.

설정 예시 (한 파서 + 게시판 목록 YAML):
```yaml
- id: jnu-scholar
  url: https://www.jejunu.ac.kr/ara/noticesurvey/outEvent.htm?category=323&pageSize=30
  type: artpq_table
  tag: 장학
- id: dorm
  url: https://dormitory.jejunu.ac.kr/dormitory/notice/notice.htm?pageSize=30
  type: artpq_table
  tag: 생활관
- id: lib
  url: https://lib.jejunu.ac.kr/pyxis-api/1/bulletin-boards/1/bulletins?offset=0&max=30
  type: pyxis_json
  tag: 도서관
```
- 수집 주기는 1~3시간에 한 번이면 충분하다. 가장 바쁜 게시판도 하루 10건 정도이고, `pageSize=30` 한 번이면 빠짐없이 받는다.
- 날짜만 있고 시각이 없다(목록 기준). "새 글" 판단은 **seq가 커졌는지**로 한다. seq는 모든 사이트에서 함께 늘어나는 번호다 [확인].
- 링크는 절대 URL로 바꿔 저장한다(목록 href는 `/ara/...` 처럼 상대 경로).

### 2-2. 중앙도서관 (Pyxis JSON)
- `GET https://lib.jejunu.ac.kr/pyxis-api/1/bulletin-boards/1/bulletins?offset=0&max=20` → `data.totalCount`, `data.list[]` [확인]
- 쓸 필드: `id`, `title`, `bulletinCategory.name`(일반공지/학술공지), `dateCreated`("2026-11-18 15:12:27"), `attachmentCnt`, `writer`(가려서 나옴)
- 목록에서 `content` 는 null이다. 글 화면 링크는 SPA 해시 경로인데 정확한 형식은 확인하지 못했다 [추측: `https://lib.jejunu.ac.kr/#/bulletins/1/<id>` 비슷한 꼴]
- `/pyxis-api/1/bulletin-boards` 는 badRequest를 돌려줬다. 다른 게시판 번호(2, 3…)는 확인하지 못했다.

### 2-3. 학사일정 (정적)
- `academic.htm?year=YYYY` 를 학기마다 한 번 받는다. `#sub-main-contents` 의 "MM.DD(요일) ~ MM.DD(요일) 내용" 꼴을 정규식으로 자른다 [형식 확인, 셀렉터 세부는 확인 안 함].

### 2-4. 한 번 실행에 드는 요청 수 (추정)
본부 공지(전체, pageSize=50) 1 + 채용 1 + 생활관 1 + 국제교류 1 + clip 3 + 도서관 1 + 기타 4~5 = **12~15 요청**. 몇 초면 끝나므로 GitHub Actions 무료 한도 안에 충분히 든다 [추측].
www 전체 목록을 `category` 없이 한 번만 받고 분류 칸으로 나누면 카테고리별로 따로 부를 필요가 없다.

## 5. 위험·한계

- robots.txt `Disallow: /` (위 0-7). 호출 빈도를 낮추고 출처를 밝힌다.
- 인증서 체인 불완전 → http로 받거나 중간 인증서를 넣는다.
- 해외(GitHub Actions) IP 차단 여부는 모른다 [추측]. 막히면 한국 IP에서 돌리는 자체 러너나 집 PC의 cron으로 바꾸는 방안을 준비한다.
- 목록 제목은 잘려 있을 수 있다 → `a@title` 을 쓴다. 본문이 이미지인 글이 많다 → 본문 요약은 MVP에서 뺀다.
- 페이지가 바뀌면 셀렉터가 깨질 수 있다. 게시판 대부분이 같은 CMS라서 한 군데만 고치면 되지만, 수집 결과가 0건이면 알림이 오게 해 둔다.
