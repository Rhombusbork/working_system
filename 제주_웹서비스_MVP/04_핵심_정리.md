# 핵심 정리 — 내 방향과 좋은 문제의 정의

12/12 기업실무 기획과제: 바이브코딩을 활용한 제주 로컬 웹서비스 MVP (1조, 내 발표)

## 1. 내가 원하는 방향

- 머리로 지어낸 문제가 아니라 **실제로 있는 문제**를 찾는다.
- 참고할 것:
  - 블로그 여행 후기
  - 지방자치단체 민원
  - 실제 의견: 아는 형이 "제주의 문화 관광지가 정리된 프로그램이 없다"고 함
- 정말 진짜 문제인지 **발로 뛰며** 확인한다 (전화, 현장).

## 2. 웹서비스로 풀기 좋은 문제란

**한 줄 정의: 특정한 사람이 자주 겪고, 지금은 불편한 방법으로 버티고 있으며, 정보를 입력하면 결과 화면 하나로 풀리는 문제.**

| 조건 | 뜻 | 근거 |
|---|---|---|
| 누가 겪는지 분명하다 | "관광객"이 아니라 "비 오는 날의 뚜벅이 여행객"처럼 좁게 | 『제로 투 원』, 평가지표 "문제 정의의 명확성" |
| 실제로 겪었다 | 의견이 아니라 과거에 일어난 일로 확인된다 | 『The Mom Test』 |
| 지금 버티는 방법(기존 대안)이 있다 | 검색 여러 번, 카톡으로 묻기, 헛걸음. 대안이 아무것도 없으면 문제가 아닐 수도 있다 | 『Running Lean』 |
| 자주 겪는다 | 1년에 한 번 겪는 문제는 다시 쓰지 않는다 | 『훅』, 평가지표 "재사용 의향" |
| 정보 문제다 | 흩어짐, 고르기 어려움, 계산이 귀찮음, 지금 상태를 모름, 절차가 복잡함 | 거래비용·탐색비용 개념 |
| 입력 → 결과로 끝난다 | 로그인·결제·DB 없이 기능 2~3개로 풀린다 | 과제 주의 사항 |

**피할 문제**
- 물리적인 문제 (길 막힘, 짐 무게)
- 사람이 많이 모여야 가치가 생기는 문제 (후기, 매칭, 커뮤니티)
- 바가지요금이나 택시처럼 규제·단속으로 풀어야 하는 문제

**한 문장 틀** (『일의 언어』 + 『무기가 되는 스토리』)
> **[누가]**는 **[어떤 상황]**에서 **[무엇을 하려는데]**, **[무엇]** 때문에 막힌다. 그래서 **[어떤 기분]**이 든다.

## 3. 진짜 문제인지 확인하는 법

| 어디서 | 무엇을 |
|---|---|
| 블로그·지도 리뷰 | 후회·불편 문장 30개를 모아 유형별로 센다 |
| 민원·불편신고 | 관광불편신고 집계(공공데이터포털), 국민신문고, 필요하면 정보공개청구 (답이 오는 데 최대 10일) |
| 공식 조사 | 제주 방문관광객 실태조사, 「데이터로 보는 제주여행 — 크루즈편」(안내소 상담 기록) |
| 전화 | 공항 관광안내소 064-742-0032 · 064-742-6051, 제주관광정보센터 064-740-6000 |
| 현장 | 박물관·미술관 매표소, 문화관광해설사, 게스트하우스, 제주대 학생 |

**물을 것**: 관광객이 가장 자주 묻는 질문, 최근 기억나는 손님 이야기, 지금은 무엇을 보여 주며 안내하는지. **내 아이디어는 말하지 않는다.**

**판단**: 블로그 / 민원·조사 / 안내하는 사람 / 기존 대안 / 테스트할 5명 / 입력 → 결과. 이 중 **세 가지 이상** 맞으면 고른다.

## 4. 형의 말에서 확인할 것

- 이미 있는 것: 비짓제주(관광 정보 전체), 플레이제주(공연·전시 일정), 젠트립(일반 여행). 박물관·미술관만 모은 서비스는 검색으로는 찾지 못했다.
- 제주에는 박물관·미술관 등이 많고 사립이 대부분이다(2016년 기준 등록 83곳 중 사립 66곳). 도에 부실·유사 박물관 민원이 많다고 했다.
- 그래서 형이 겪은 문제가 셋 중 무엇인지 가려야 한다:
  - **없다**: 정리된 곳이 아예 없음
  - **못 고른다**: 많은데 어디가 볼 만한지 모름
  - **틀렸다**: 휴관일·운영시간이 달라서 헛걸음
- 형에게 물을 것: "마지막으로 그걸 느낀 게 언제였어? 그때 실제로 어떻게 찾았어? 1년에 몇 번 그래?"
